## Deviations / known limitations

- UPDATE-PROBE MODE — this run installs the previous exact artifact through the official CLI, then updates to the candidate through the running Host plugin manager and asserts the in-process transition only. It is not a fresh-install acceptance run; the same scope still needs an ordinary schema-v2 run on the final candidate.
- SCOPE — this run covers DSH 0.2.2-rc.5 + Web Profile + Chrome only. The DSH 0.2.1-rc.3 Desktop/macOS target is covered by the separate real-Electron desktop evidence; Windows and Web Edge are not-supported and are not claimed.
- HONEST GAP — docs/design/implementation-plan.md §20 "at least one safe layout capability actually effective" cannot be met on DSH 0.2.2-rc.5: the certified adapter (installed-package) exposes no public density / transcript-width / message-flow hook (all three capability facts are unavailable). Livery degrades layout to host/stock and reports the unavailable capabilities in the self-check rather than faking them. Wallpaper is removed from schema v1.
- Disable/hot-reload state-machine transitions and unknown-version fail-closed to stock are covered by unit/contract tests; this black-box run proves install → boot → stock start → panel config apply → hard reload → restore stock → official uninstall → restart residue (web) / install-admission + app-runtime boot (desktop).
- §18.8 p95/CLS statistics need ≥30 samples per scenario; this run records per-run byte budgets and one cold-start paint trace/filmstrip, not a statistical distribution.
- DSH 0.2.2-rc.5 serves client bundles only through boot-graph grouped URLs (plugins/??<pkg>/client.js&rev=…); the bare /plugins/<pkg>/client.js?rev= form returns 404 in this build (asserted as a documented warning).
- No automatic Playwright browser download is used: the harness drives the system Chrome through channel: 'chrome' (or an explicit --chrome-binary matching the frozen certified version) for the web carrier, and connects over CDP to the Electron renderer (desktop).
- Web Profile + Chrome only: desktop macOS/Windows native-window criteria, packaged-app runtime claims and Edge coverage are explicitly not-supported for this release line (not pending, not claimed).
