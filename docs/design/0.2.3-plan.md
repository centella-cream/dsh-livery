## 1. Release goal

`0.2.3` is a **client-only feature + robustness release** on the same eight
exact-certified host adapters:

1. **Source target: 2 new offered sources; 3 offered total.** Wikimedia Commons
   (existing) plus **Cleveland Museum of Art** and **The Metropolitan Museum of
   Art**. Both are keyless, CC0/public-domain filtered, and use a dedicated
   direct-image layer because their image CDNs do not expose CORS. This is a
   target, not a commitment: if the Met gate fails or M1 cannot fit the effect
   pipeline within 634 B, 0.2.3 ships **one new source** and says so.
2. **No client gzip increase.** Keep the 0.2.2 cap of `73,728 B`; the published
   build is **73,094 B gzip / 278,802 B raw (634 B headroom)**. New providers
   are data in a Host route, not per-provider client code. A generic manifest
   engine, the direct-image layer, the `buildWallpaperCss` direct-emission
   refactor and the legacy notice share the bytes freed by removing the unused
   Openverse fetch implementation; if that is not enough, trim/defer a source.
   **Do not raise the cap.**
3. **Direct-image layer, not raw CSS.** Direct wallpapers are rendered by a
   plugin-owned `<img>` layer with `referrerpolicy="no-referrer"` and an
   `onerror` fallback; the existing `backgroundImageValue()` invariant (remote
   only from the verified cache object URL) stays intact for cached/upload
   wallpapers. No raw remote URL in body CSS.
4. **Close the 0.2.2 Openverse notice defect.** Stored legacy Openverse
   selections, presets and Recent entries must show the ToS notice; the gate must
   make that requirement machine-checkable. Openverse is not re-offered.
5. **Finish the visual evidence** for real jobs popover/subagent cards and the
   stock-plus-wallpaper menu surfaces; add a real rendered check or a named
   manual screenshot on the final candidate.
6. **Fix the high-value robustness items**: sidecar race, detail boundary/action
   reactivity, stale-retry deadline, large-image feedback, pagination and
   direct/manifest security.
7. **Record a real `0.2.2 → 0.2.3` Web update transition.** The current
   `STALE_BOOT_VERSIONS` is exactly `['0.2.1']`; 0.2.3 must include `0.2.2`.

It does **not** add a backend proxy, key-based providers, a Host update API, a
new host adapter, Windows/Edge support, or an attempt to change the host
Modal/Settings mask (host-owned; see §10).

### 3.2 Gate rules for new sources

Add the candidates to `docs/research/provider-access-gate.json` only after:

- API CORS/preflight observed with `Origin`;
- at least one image host observed in a real browser (`naturalWidth > 0`),
  including a repeat probe for Met;
- licence/attribution fields identified, including a `license: null` /
  non-selectable rule where the source cannot establish reuse rights;
- no key/login/back-end dependency;
- rate-limit behaviour observed and mapped to a one-batch policy;
- terms/attribution/notice clauses quoted and linked;
- image host allowlist exact/wildcard with dot-boundary matching;
- an explicit `delivery: 'cached' | 'direct'` and a browser probe record.

The gate schema must **refine/extend** the existing record, not pretend these
are all new fields:

- `delivery`: new `cached | direct`;
- `imageHostCors`: the existing free-text/prose `cors.imageHostCors` (already
  present for openverse/wikimedia/nasa/met/aic/picsum) is refined into the
  enum `verified | absent`; `absent` is valid only for `direct` and requires the
  browser probe;
- `browserImageProbe`: new URL, observed width/height, browser/version, date,
  repeat count;
- `notice`: new optional structured `{ text, appliesTo }` for providers such as
  Openverse; absence is meaningful (the current file has no `requiredNotice`
  field, only prose notes).

`verify-provider-gate.mjs` must read the **provider manifests** (not the current
`ProviderId` union in `providers.ts`), validate registered **and offered** ids,
and cross-check each manifest's API origin, imageHosts, delivery, licence and
notice fields against its accepted gate row. A new provider with no accepted
row, or an offered provider with an unaccepted row, fails `release:check`.

### 3.3 Openverse — decision closed

Openverse is **not** a 0.2.3 candidate:

- I re-tested `api.openverse.org` (image search, `/v1/images/`, `/v1/`) three
  times; all three timed out after 25 s from the review network.
- Openverse’s official [Authentication and Throttling](https://docs.openverse.org/api/reference/authentication_and_throttling.html)
  documents OAuth rate tiers; the 0.2.2 gate recorded anonymous **20/min +
  200/day**, with registration required for higher limits.
- There is **no supported bypass**. Using more than the anonymous allowance
  requires OAuth credentials and a secret-storage UX this keyless plugin does
  not have; circumventing it would violate the API terms.
- The 0.2.2 removal was correct. Openverse stays legacy-only; the 0.2.3 work is
  the **notice** for already-stored Openverse images, not new requests.
- **Cold-cache legacy behavior is fail-closed.** If a stored Openverse Recent
  entry or preset has no local Blob (cache cleared/evicted), re-applying it must
  show the notice + a “not available offline; re-select a source” fallback and
  must **not** call `api.openverse.org`. Deleting the Openverse fetch
  implementation must not leave a `commitRemote()` path that silently attempts
  the removed provider; add a test for the cold-cache Recent/preset path.
- If ever added again, it must be a separate **authenticated/OAuth key source**
  (0.2.4+), not a keyless provider.

## 4. Architecture — Host manifest route, direct `<img>` layer

### 4.1 Manifest delivery: new exact Host route

Do **not** put provider manifests in the style catalog. The catalog is a
grammar-versioned, hash-bound style document; adding providers would change
`LiveryCatalog`, `CATALOG_GRAMMAR`, `catalogHash`, `isCatalogShape()` and every
scope's catalog verification for data that is not style data. Do **not** use the
image asset route; it only serves image files.

Choose a new exact Host data route:

```
GET /livery/api/providers
```

Contract:

- JSON `{ schemaVersion: 1, manifestHash: string, providers: ProviderManifest[] }`;
- `Cache-Control: no-store` (providers are small; avoid stale manifests);
- `404` when the plugin is inactive or the host has no accepted adapter,
  matching the existing route fail-closed behaviour;
- a malformed/unsupported manifest is a `500` (or no route) and the client shows
  an unavailable-online state; never a partial provider list;
- the route is registered with the existing `WebServer` exact-route API and
  covered by host/client tests for shape, hash, 404, cache headers and
  malformed data;
- no catalog hash/grammar change; no 13-scope catalog revalidation is forced by
  this route, but the route itself is part of the 0.2.3 host contract and
  acceptance;
- the client fetches the route lazily when the Online tab opens/mounts (the
  default tab now performs one automatic Random batch), never at app boot; a
  failed fetch leaves no online sources and a visible reason.

The Host bundle budget is 15,506 / 368,640 B gzip; the route/code fits. The
manifest JSON is in the tarball, not in `lib/client.js`.

**Manifest source-of-truth (N4):** `src/provider-manifests.json` is imported by
the Host provider module and bundled into `lib/index.js` (host gzip budget, not
client). The gate script reads that same source JSON; there is no separate
runtime file whose packaging could be forgotten. Add a build/route test that the
bundled manifest hash equals the source file hash. If a separate JSON runtime
file is ever chosen instead, it must be added to `package.json.files` and
`pack:check` in the same change; that is not the 0.2.3 plan.

### 4.2 Provider manifests and generic engine

The route serves **data**:

- each `ProviderManifest` declares id, labels, auth `keyless`, delivery, API
  origin/path, query/detail templates, result paths, image fields, licence and
  attribution mapping, imageHosts, capabilities and rate policy;
- the client ships **one generic provider engine** that validates a manifest and
  executes list + optional detail requests; it does not contain Cleveland/Met
  code;
- adding/replacing a source is a manifest change, not a client bundle change;
- manifests are trusted shipped data, but the client validates them strictly
  (unknown fields, non-https/non-allowlisted hosts, oversized result sets,
  invalid mappings) before any request;
- a provider-specific quirk such as Met’s search-then-object flow is a generic
  `detail` template, not a bespoke module.

Wikimedia can keep its existing imageinfo implementation; the new sources are
manifest-driven. A later version can migrate Wikimedia.

The client code additions (generic engine + direct layer + notice) are measured
against the bytes freed by deleting the unused Openverse fetch implementation.
If they do not fit, trim/defer a source; do not raise the cap and do not assume
lazy-load works.

### 4.3 Cached vs direct delivery

```ts
type ProviderDelivery = 'cached' | 'direct'
```

- `cached`: current Wikimedia path (fetch → validate → Blob → IndexedDB →
  object URL).
- `direct`: browser displays a provider-controlled image URL through a
  plugin-owned `<img>` layer; no Blob, no IndexedDB.

The existing security comment in `backgroundImageValue()` remains binding:
remote wallpapers in **body CSS** are only rendered from the verified local
cache object URL. Direct mode must not relax that function; it uses a separate
layer.

### 4.4 Direct `<img>` layer and security

Direct wallpapers are rendered by a dedicated plugin-owned `<img>` layer, not
body `background-image`:

- fixed/full-viewport `<img>` with `object-fit: cover`, `pointer-events: none`,
  behind the app content (the same visual position as the current body
  background);
- `referrerpolicy="no-referrer"` on the `<img>`;
- `onerror` hides the layer and shows a visible failure with a thumb/stock
  fallback; CSS background images have no `onerror`, which is why CSS is not
  used;
- the `<img>` request is browser-managed: it may still send host cookies and the
  document's other browser defaults; the plan does **not** claim
  `credentials: omit` for direct images. Direct providers are allowlisted hosts
  and no credentials are placed in the URL; the remaining cookie behaviour is
  documented as a direct-mode boundary;
- direct URL must be provider-controlled, on the manifest `imageHosts`
  (exact/wildcard, dot-boundary), https, no credentials, bounded length; **no
  arbitrary user-supplied direct URLs**. Implementation: the client keeps a tiny
  reviewed `DIRECT_IMAGE_HOSTS` map (`cleveland`, `met-open-access`) and rejects
  v3 preset/state records whose `provenance.providerId` is missing/unknown or
  whose full/thumbnail URL is not on that exact host; the map is unit-tested
  against `src/provider-manifests.json` so it cannot drift silently;
- no fetch means no content-type/byte-size/decode/final-URL checks. Cleveland
  provides `images.*.filesize` and dimensions but direct mode cannot enforce a
  byte cap before the browser loads; Met’s object record has no pixel dimensions
  or file size. Met uses **`primaryImage`** for the wallpaper (fallback
  `primaryImageSmall` on load error/timeout), records the sample 8.29 MB original
  and makes **no 15 MiB/40 MP precheck claim**; the direct mode section must not
  state a universal byte cap;
- direct image load failure is visible and falls back to the provider thumb or
  stock; no silent blank;
- no Blob/object URL, so `clearLocal`/quota paths skip direct entries;
- no direct provider may contribute HTML/SVG with scripts; `<img>` display only.

### 4.5 Wallpaper effect pipeline for direct images

This is the blocking design contract the first 0.2.3 plan missed. The current
pipeline is:

```text
backgroundImageValue(selection) -> image
buildWallpaperCss:
  if (image === undefined) return ''          // wallpaper.ts:744
  ::before background-image/filter: blur      // :749-750
  ::after dim veil                            // :756-758
  atmosphere background-image/mix-blend       // :778-787
  frost token overrides                       // :801-823
```

A direct selection has no object URL, so `backgroundImageValue()` returns
`undefined` and `buildWallpaperCss` returns `''` before **frost, dim, atmosphere
and blur** are emitted. A bare `<img>` without frost leaves the host surfaces
opaque, so the wallpaper is hidden; this is a functional failure, not a cosmetic
one. It must be fixed before M1.

Frozen contract:

- Add a direct/image-mode input to `buildWallpaperCss` (e.g.
  `imageLayer: 'body' | 'direct'`). When `imageLayer === 'direct'`:
  - **do not** emit the `::before` body `background-image` or its `filter`;
  - **do not** early-return on `image === undefined`;
  - still emit `body[data-dsh-wallpaper]{background-color:transparent}`, the
    `::after` dim veil, the stock/livery frost token blocks and the
    accessibility rules;
  - **do not emit the CSS atmosphere rule** (`.wallpaper-overlay{background-
    image:...}`); direct has no object URL and no second `<img>` in 0.2.3;
- direct image element:
  - a fixed wrapper (`position:fixed; inset:-24px; width/height:calc(100% +
    48px); z-index:-1; pointer-events:none`) with an `<img>` at
    `width/height:100%; object-fit:cover; object-position:<focal>; filter:
    blur(<effects.blur>px)`. The 24px overhang is the **same edge-bleed fix as
    the body `::before` (`inset:-24px`)**, not an undefined scale; no blurred
    transparent edge is allowed;
  - `referrerpolicy="no-referrer"`; `onerror` hides and shows the fallback;
  - the wrapper is plugin-owned and leased through the existing wallpaper layer
    owner (see §4.6); `clear()` removes it; HMR/multi-instance must not leave a
    stale direct `<img>`;
- dim:
  - the same `::after` rgba veil is emitted (or a sibling dim element inside the
    direct wrapper); it must paint above the direct image and below app content;
- atmosphere:
  - **0.2.3 direct has no atmosphere.** Do not create a second `<img>` and do
    not emit the CSS atmosphere rule. The controller must remove any existing
    overlay for a direct selection; the UI says “atmosphere is unavailable for
    this source” rather than silently showing an unexplained missing effect;
  - this also avoids a second full-size image download on a CDN whose
    `Cache-Control` is not recorded by the gate; a future direct atmosphere
    needs a second `<img>`, a CDN cache probe and its own budget, not this
    release;
- style wallpapers and cached/upload wallpapers keep the existing body
  `::before` path unchanged; `backgroundImageValue()` remains object-URL-only
  for those;
- focus/blur: direct uses `object-position` + `<img>` `filter`; the current
  body `background-position`/`::before filter` is not reused;
- dark/light: a direct provider image is the same URL in both modes; no
  dark-image variant is invented;
- forced-colors/reduced-transparency: hide the direct layer (and the cached
  atmosphere, if any) with the existing decorative selectors; frost is not
  emitted in those modes;
- tests: direct CSS contains dim/frost/accessibility and **no** body
  `background-image` and **no** CSS atmosphere rule; direct DOM has the `<img>`,
  focal `object-position`, blur `filter`; **no direct atmosphere `<img>`**;
  the hero atmosphere sublayer is hidden for direct; forced-colors/
  reduced-transparency hides the direct layer; no raw URL in CSS.

This refactor is **new client bytes** and must be included in the M1 budget
spike; there is no second atmosphere layer in 0.2.3, which lowers the byte risk.
The hero atmosphere sublayer must also be suppressed for direct and counted in
the UI contract.

### 4.6 State, preset and Recent downgrade

- **Schema v3 only for direct selections.** Cached/builtin/upload selections
  keep writing v2, so a 0.2.2 downgrade does not lose ordinary wallpapers.
  Direct selections write v3; a 0.2.2 parser must fail closed to no wallpaper
  (frozen-parser test), never fetch the direct URL.
- **Preset v3 only for direct targets.** Cached/builtin/upload presets stay v2;
  0.2.2 imports them. A direct preset is rejected by 0.2.2's existing
  unknown-schema/unknown-field path, not half-applied.
- **Direct Recent entries use a new key** (e.g.
  `dsh-livery.wallpaper.recent.v2`); the 0.2.2 client only reads the v1 key and
  therefore never sees/fetches a direct Recent entry. 0.2.3 reads both keys,
  merges for display, and never writes a direct entry to the v1 key. The v2
  writer must persist **providerId + delivery**; otherwise re-applying a direct
  entry loses “direct” and falls back to the cached fetch. Add a writer test
  that round-trips providerId/delivery through `addRecentEntry`/`parseRecentEntry`
  and a re-apply test that never calls `cacheRemoteImage`/`loadCachedRemote`.
- Every direct entry point must bypass the cache: panel selection, preset apply,
  Recent re-apply, reload/mount, controller apply and clear. `cacheRemoteImage`,
  `loadCachedRemote` and `commitRemote` must not run for direct; add tests for
  each path; `clearLocal` leaves direct state alone.
- **The direct layer is the only full-size consumer.** The hero preview and
  result grid use the provider `thumbUrl` (Met `primaryImageSmall`, Cleveland
  `web`); never load `primaryImage`/`print` into the hero or grid. The hero
  atmosphere sublayer (`wallpaper-hero__atmo`) is hidden for direct. A **reload
  with network** re-fetches the remote image; a reload offline cannot restore
  it (no Blob cache). Do not use “survives a reload” without the online
  qualifier: the acceptance item is `wallpaper.direct-online-reload`, and the
  offline fallback is documented.
- **DOM lease.** The direct wrapper and any overlay must be created/removed by
  the existing `createWallpaperLayer` owner lease (same as the style/overlay
  elements); use a stable id/class, reverse-order teardown, and HMR/multi-
  instance tests so no stale `<img>` survives. A direct `clear()` must remove
  the wrapper, dim overlay, cached atmosphere and body attributes together.
- **Storage identity model.** 0.2.3 will have main state v2/v3, preset v1/v2/v3,
  Recent v1+v2 and the style sidecar. Define one identity/ordering rule
  (`revision`, `sourceId`, selection/delivery) shared by all keys; do not repeat
  the sidecar's check-then-act guard independently on the new keys. Add a
  cross-key arbitration test; this is a P2 consolidation, not a reason to keep
  five ad-hoc protocols.

### 4.7 Provider manifests for 0.2.3

**Cleveland** (`openaccess-api.clevelandart.org`):

- `GET /api/artworks/?q=<query>&has_image=1&cc0=1&limit=12&skip=0`
- map `title`, `creators[].description`, `creation_date`, `url`,
  `images.web`/`images.print`; `share_license_status` must be CC0;
- the manifest is hard-coded to the `web` (thumb) and `print` (wallpaper)
  fields; `full` TIFF is never selected. Direct mode has **no byte cap
  guarantee**: the API's `filesize` can be used for a UI warning but cannot stop
  the browser from loading a changed asset. Do not keep the old “under the byte
  cap” wording;
- direct `<img>`; credit “Cleveland Museum of Art” + object URL.

**Met** (`collectionapi.metmuseum.org`):

- `GET /public/collection/v1.1/search?q=<query>&hasImages=true&limit=20&offset=0`
  (the old `/v1/search` retires 2026-10-01); over-fetch 20 because
  `isPublicDomain`/`primaryImage` filtering is sparse, then return up to 12
  valid results and note a short Met page in the UI;
- fetch each returned object; accept only `isPublicDomain === true` and a
  provider `primaryImage` https URL;
- **Product decision (N2): use `primaryImage` for the wallpaper, pinned-only,
  with an explicit “Met may load a large original” UI hint; `primaryImageSmall`
  is only thumb/error fallback.** Met has no pixel/file-size metadata, so direct
  mode cannot precheck 15 MiB/40 MP; record the gate sample (8.29 MB original)
  and the browser load timeout/fallback. Do not leave both renditions as
  interchangeable “or” choices. If product rejects the unbounded original, the
  only alternative is `primaryImageSmall` with a documented 600 px quality
  limit; 0.2.3 chooses `primaryImage` for wallpaper quality and accepts the
  explicit risk;
- one search + N object requests per batch; **concurrency 4**, per-attempt
  budget 6 s and overall 12 s; partial object successes are kept; all failures
  produce a typed failure, not a silent empty;
- respect the 80 req/s guideline;
- direct `<img>`; credit “The Metropolitan Museum of Art” + `objectURL`;
- Met is conditional on a repeatable browser image probe: **3 runs across two
  networks/days**, plus a real DSH Web and Desktop `<img>` check; one headless
  probe is not enough.

## 5. UI, Auto and request policy

- Keep the four source tabs; the Online provider `<select>` lists `Auto` then
  the offered providers. No new source-picker surface.
- User-requested 0.2.3 adjustment: the Wallpapers page defaults to the Online
  tab and performs exactly one automatic Random batch per panel mount (so
  re-entering the page starts a new batch). In-page source-tab switches do not
  refetch. Switching to a **direct** provider auto-loads that provider's default
  `browse` batch (because direct sources are search-only and Random is
  unavailable); switching among cached providers still clears without an
  implicit fetch.
  (This supersedes the earlier "no request on panel mount" policy.)
- `AUTO_MAX_ATTEMPTS` remains 2. Auto priority is **Wikimedia, then Cleveland**;
  Met is offered but **pinned-only**, because a Met batch is one search + up to
  12 object requests and cannot reliably fit two Auto attempts. Document this
  and test it. If the product wants Met in Auto, it must be a deliberate
  three-attempt/priority decision with a measured deadline, not an implicit
  “tries offered providers.”
- Cleveland/Met are search-only; Wikimedia search + random. Auto returns the
  provider that served, and a pinned provider never silently switches.
- **Delivery switching is a renderer switch, not a CSS tweak.** When Auto serves
  Wikimedia (cached) after a direct selection, or vice versa, the controller must
  tear down the body `::before` path, the direct `<img>` and the cached
  atmosphere together, then apply exactly one mode. Never leave a stale body
  background, a stale direct `<img>`, or a cached atmosphere over a direct
  image. Add a test that alternates cached→direct→cached through Auto and
  asserts one active renderer, no stale atmosphere, and the same frost/dim
  behavior.
- Direct providers show a small “online only / not cached / atmosphere
  unavailable” hint; do not hide the tradeoff.
- Show provider name, licence, creator, source link; preserve attribution in
  presets/Recent/legacy.
- The Openverse notice is a persistent, prominent line for selected/served/
  persisted legacy provenance; it is not tied to transient Online state only.
  No Openverse request is made.
- Empty/loading/timeout/rate-limited/unavailable/invalid states stay explicit;
  direct image failure is a visible state, not a blank.

## 6. Defect and vulnerability register

Severity is for 0.2.3 planning. “Confirmed” means code/docs were inspected in
this repo; “hardening” means a design risk to close before shipping direct mode.

### P0 — legal/compliance

1. **Openverse notice was removed in 0.2.2 while legacy selections still
   render.** Commit `1f00c8d` deleted `openverseNoticeVisible` and the
   `wallpaper.online.openverseNotice` i18n key; `PROVIDERS` still resolves
   `openverse` for stored data. The gate note requires the notice. A user with a
   0.2.1 Openverse wallpaper sees the image with no notice. **Fix in 0.2.3 even
   though Openverse is not re-offered.** Add a legacy notice path + tests for
   selection, preset and Recent.
2. **The gate has no machine-checkable notice field.** The gate file has no
   `requiredNotice` member at all; the Openverse requirement lives only in
   prose notes. Add a versioned `notice` schema (`{ text, appliesTo }`) and a
   `verify-provider-gate`/acceptance check; otherwise a future provider can lose
   its notice without failing the gate.

### P1 — release/feature blockers

3. **Single offered source / no failover.** `OFFERED_PROVIDERS` is Wikimedia
   only; `autoProviders()` returns one. A Wikimedia outage leaves the Online tab
   empty. This plan adds two.
4. **No direct-image path, and the effect pipeline is anchored on the cached
   image.** Cleveland/Met/NASA image CDNs have no ACAO; the current
   fetch→Blob path cannot use them. Without direct mode the only possible new
   source is Openverse, which is rejected. Worse, a bare `<img>` is not enough:
   `buildWallpaperCss` early-returns at `image === undefined` before frost/dim/
   atmosphere/blur, so the plan must freeze §4.5 before M1. This is a
   functional blocker, not a styling detail.
5. **Client gzip is 73,094 B with 634 B headroom**, not 73,632/96 B. The plan
   must stay under 73,728 with no cap change: Host-route manifests, remove the
   dead Openverse fetch code, a generic engine, direct `<img>` layer and trim/
   defer if needed. Do not raise the cap.
6. **Host floating-surface visual evidence is still incomplete.**
   `visual.jobs-popover-opaque` and `visual.stock-wallpaper-menu-opaque` are
   explicit skips; the 0.2.1 card-opacity fix is code-correct but not visually
   re-proven in the real jobs/subagent/stock surfaces. Add a real rendered check
   or a named manual screenshot on the final candidate.
7. **0.2.3 won’t hot-update from 0.2.2 yet.** `STALE_BOOT_VERSIONS` is exactly
   `['0.2.1']`; include `0.2.2`, and run the update probe from the published
   0.2.2 tarball. Do not infer this from 0.2.1→0.2.2.

### P2 — correctness/robustness

8. **Sidecar write/clear guard is check-then-act.** `style-store` reads the main
   identity and then writes/removes the sidecar; a winning tab can interleave
   between read and write. It is a narrow race but can lose a style. Add a
   per-identity guard or a single-writer protocol; test an interleaved winner.
9. **Legacy v1 preset/Recent provenance has no providerId, and direct Recent
   writes must preserve providerId/delivery.** Old Openverse presets/Recent
   entries cannot show the notice via `credit.providerId`; infer from
   source/sourceURL for legacy records, or add a legacy notice rule; test v1.
   For direct mode, the Recent v2 writer must round-trip `providerId` +
   `delivery`; otherwise a direct re-apply loses “direct” and falls back to the
   cached fetch. Add both tests.
10. **Detail boundary unknown state falls back to “valid”.**
    `detailBoundaryKey` returns `detail.boundary.valid` for any unknown state;
    add an unknown-state key or fail closed to a neutral boundary.
11. **Detail actions don’t react to main-panel registration changes.**
    `isMainPanelRegistered` is a mutable closure without a subscription; after
    HMR the “Open Livery” action can stay hidden or visible incorrectly.
12. **Stale catalog retry can take ~70 s** (`8 × 8 s` + backoff) while the old
    boot CSS remains in the DOM. Add a total deadline and clear boot artifacts
    on expiry; do not let a stale frame linger.
13. **No pagination.** `nextCursor` is stored but no UI consumes it; every
    source returns one 12-result page. Add a “Load more” per provider or
    explicitly document one-page-only and remove the dead field.
14. **Large remote originals show only the generic `wallpaper.downloadFailed`.**
    The panel does show an error, but it cannot distinguish an oversized
    original or fall back to the thumb. Add a specific “too large” message and
    thumb fallback.
15. **Custom URL to a CORS-less public image fails as a generic network
    error.** The 0.2.3 decision is **no custom direct path** (custom URLs stay
    on the cached path); show a precise “this host does not allow browser
    downloads” message instead. Do not add an arbitrary direct URL exception.
16. **Provider JSON fallback is not stream-capped when `response.body` is
    absent.** `readCappedJson` falls back to `response.text()` and checks the
    size after materializing. In supported browsers the stream path is used, but
    harden the fallback.
17. **DNS-rebinding risk in the custom URL path.** Host validation is
    hostname-only; a public name can resolve to a private address. Document the
    browser Private Network Access boundary and add a resolution-agnostic
    fail-closed test if the platform provides one.
18. **Direct-mode security is new surface.** No fetch means no content-type,
    byte-size, decode or final-URL checks; §4.4 must be enforced and tested. Do
    not let direct mode accept arbitrary user URLs, and do not claim
    `credentials: omit` for browser-managed images.
19. **Manifest validation is new attack surface.** Manifests are shipped data,
    but the generic engine must reject unknown fields, non-https/non-allowlisted
    hosts, oversized result sets and invalid field mappings before any request.

### P3 — precision/docs

20. The stable-host waiver applies one generic “Desktop has no runtime detail
    check” text to both `0.2.1-rc.2` (Web) and `0.2.1-rc.3` (Desktop); make the
    waiver host-specific.
21. CHANGELOG has two overlapping Openverse-notice entries; merge them.
22. Per-livery/boot CSS cap remains 14 KiB because of a legacy typography probe
    fixture; shipped max is 10,366 B. Consider trimming the fixture rather than
    keeping a raised cap.
23. **Host Modal/Settings boundary is already documented** in
    `docs/verification.md`; keep it as a no-action note, not a new blocker.
24. The Chinese docs index now links the 0.2.3 plan alongside the English index;
    keep both in sync for later edits.

## 7. Client budget — no increase

Published 0.2.2 measurements: **client 73,094 B gzip / 278,802 B raw**; host
15,506 B gzip; max livery CSS 10,366 B; tarball cap 4 MiB. Headroom is **634 B**.

0.2.3 must keep the client gzip at **73,728 B or less**. No cap change.

How the source expansion stays within it:

- provider manifests (Cleveland/Met) are served by the new Host route as data,
  not imported into `lib/client.js`;
- the generic manifest engine is one small code path shared by both sources;
- the unused Openverse fetch implementation is deleted (legacy needs only
  metadata/notice; no new request is possible);
- the direct `<img>` layer is one shared path, not per-provider;
- **the `buildWallpaperCss` direct-emission refactor is new bytes**; it is part
  of this budget, not free. The current early return/frost/dim/blur pipeline
  must be decoupled as described in §4.5. Direct has no atmosphere in 0.2.3,
  so there is no second `<img>` byte cost;
- if the measured delta still does not fit, trim non-essential copy; if that
  fails, **defer a source**. Do **not** assume lazy-load works: the current
  client is a single CJS bundle and the DSH loader’s extra-chunk behavior is
  unproven. A lazy-load option needs its own M1 proof; it is not the fallback.

The manifest data adds to the host/tarball budgets, which have room (host
15,506 / 368,640 B; tarball ~3.42 / 4 MiB). It does not change the catalog
grammar/hash.

The M1 spike must produce a measured `clientGzip` before M2 commits to both
sources. If generic engine + direct layer cannot fit, ship one source
(Cleveland) within the cap and defer Met; never raise the cap.

## 10. Non-goals

- No Host fetch proxy, backend, key storage or API-key UI in 0.2.3.
- No Openverse re-add; no bypass of its auth/rate limits; legacy notice only.
- No Pexels/Unsplash/Pixabay until a separate 0.2.4 key-based-source decision;
  keyed sources are not a 0.2.3 fallback.
- No new host adapter, Windows/Edge support, or update button.
- No attempt to lighten the host Modal/Settings mask; it is host-owned.
- No Host update API or pre-update preflight.
- No custom direct URL path; custom URLs stay cached-only.
- No claim that a source is offered before its gate row and browser evidence are
  committed.

## 11. Workstreams and milestones

**M0 — gate and decisions (1–2 days).**
Cleveland gate row + browser image probe; Met repeat probe (3 runs, two
networks/days, real DSH Web and Desktop); decide the fallback if Met fails (NASA
keyless or one-source re-scope); confirm no Openverse/keyed fallback. Freeze the
new Host-route/manifest schema, the direct `<img>` contract and the **§4.5
effect-pipeline contract** (frost/dim/blur, **no direct atmosphere**, focal/
blur on `<img>`, hero atmosphere suppressed).

**M1 — architecture and budget spike (2–3 days).**
Host route + manifest schema + generic engine; direct `<img>` layer;
`buildWallpaperCss` direct-emission refactor (no direct atmosphere); state
v3 (direct only), preset v3, Recent v2 key; 0.2.2 downgrade tests; direct
security rules; delete Openverse fetch; **measure clientGzip** with the effect
refactor included; prove whether lazy-load is even possible; do not assume it.

**M2 — implementation (3–5 days).**
Cleveland + Met manifests; source selector; direct UI; direct effect pipeline
(frost/dim/blur/focal; no direct atmosphere); renderer switching
cached↔direct; attribution;
failure states; i18n; manifest validation; Auto policy (2 attempts, Met
pinned-only); Met batch concurrency/partial results; budget fit (trim/defer if

**M3 — verification (2–3 days).**

Docs/CHANGELOG/README (English + Chinese); screenshots; candidate;

## 12. Risks

- **Met Imperva**: the image host has returned HTML challenges; if the repeat
  browser probe is not stable, re-scope to NASA or one source; do not claim two
  new sources.
- **Effect-pipeline refactor**: the current `buildWallpaperCss` early return
  would leave frost/dim/blur unset for direct; the refactor is unbudgeted until
  M1. Direct has no atmosphere in 0.2.3, so there is no second `<img>`; if the
  refactor does not fit in 634 B, ship one source.
- **Manifest/route size**: if the generic engine + direct layer exceeds the
  freed Openverse bytes, trim or ship one source; lazy-load is unproven and is
  not a silent escape hatch.
- **Direct-mode compatibility**: a schema mistake could make a 0.2.2 client
  fetch a CORS-less URL; the downgrade tests for state, preset and Recent are
  mandatory.
- **Legal**: a new source’s terms/attribution may be incomplete; no source ships
  without a gate row.
- **Budget**: 634 B headroom; M1 is a hard go/no-go.
- **Visual evidence**: the isolated host shell may not expose the jobs popover;
  a named manual screenshot is acceptable only if the limitation is recorded.
