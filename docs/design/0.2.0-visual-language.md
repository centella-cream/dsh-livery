# 0.2.0 Visual Language

Target version: 0.2.0. This note is the source of truth for the 0.2.0 visual
changes. It is intentionally narrower than the review backlog: token-only
styling is a hard boundary.

## Goals

1. Make 0.2.0 visibly different from 0.1.9, not only a protocol/evidence release.
2. Give Chinese users real font choices. Before 0.2.0 every Chinese UI stack was
   `system-cjk`; style differences were only visible in Latin text.
3. Give each style a stronger label hierarchy: primary, secondary, tertiary,
   captions and links must be distinguishable without changing the host layout.
4. Keep borders coherent per style. The DSH token contract only exposes border
   **color** tokens (`--dsw-alias-border-l1..l4`), not `border-style`,
   `border-width` or `border-image`. Dashed/wavy/jagged borders on DSH modules
   are therefore out of scope under token-only styling. Livery-owned surfaces may
   use them.
5. Sidebar legibility: the sidebar must stay visibly distinct from the main
   column, keep text readable over wallpapers, and retain some wallpaper
   translucency. Exact alpha parity with the main column is not a goal because the
   DSH macOS compositor owns the final wash/tint composition.

## Typography

New local CJK stacks (no network fonts):

| id | stack | intended use |
| --- | --- | --- |
| `system-cjk` | PingFang / Microsoft YaHei / Noto Sans CJK | default UI |
| `humanist-cjk` | Hiragino Sans GB / PingFang | warm UI |
| `serif-cjk` | Songti / Noto Serif CJK | editorial, paper |
| `kai-cjk` | Kaiti SC / STKaiti / Noto Serif CJK | poster, poetic |
| `fangsong-cjk` | FangSong / STFangsong / Noto Serif CJK | manuscript, print |
| `rounded-cjk` | Yuanti SC / Hannotate SC / PingFang | soft, capsule |

The host exposes only `--dsh-font-family-text` and `--dsh-font-family-code`.
There is no per-module font-family token. A style can therefore choose UI,
content and code families, but cannot assign a different family to each host
module.

Label hierarchy is expressed with the existing alias label tokens and per-style
contrast repair. No host selectors are used.

## Borders

- Allowed: border colour, contrast, radius, elevation/shadow, double-line
  treatment on Livery-owned cards.
- Not allowed on DSH modules: `border-style`, width recipes, dashed/wavy/jagged
  borders. Those require a future host token or a relaxation of the token-only
  rule.
- L5a decorations (`studio-grid`, `studio-dots`, `studio-frame`, `studio-rules`)
  remain the only large-area per-style pattern.

## L5a assignment

`presentationFromLayout` derives a decoration from the surface style:

| surface | decoration |
| --- | --- |
| terminal | studio-grid |
| brutal | studio-dots |
| pill | studio-dots |
| paper | studio-rules |
| editorial | studio-rules |
| sharp | studio-frame |
| flat | studio-grid |
| soft | studio-dots |
| rounded | studio-dots |
| elevated | studio-frame |
| solid / glass | none |

v2 manifests can override this with an explicit `studioDecoration` recipe.

## Sidebar

Target: legibility, not alpha parity.

- The main column keeps the wallpaper frost at `100 - frost`.
- The macOS sidebar keeps the host's own tint/wash composition. Livery supplies a
  frosted fill at `min(94, 100 - frost + 20)` and accepts the host's 40/50 %
  multiplier, so the rail is more legible than the main column's 65 % fill while
  still showing a wallpaper trace.
- Acceptance reads the real `sidebarCol` DOM background (colour + image), records
  the observed composite, and checks text contrast rather than equality with the
  main column.
- The sidebar must keep at least a visible wallpaper trace; it is not turned into
  an opaque panel.

## Responsive rules

- Style preview and copy stay side by side while the Livery container is at least
  640 px wide.
- Below 640 px they stack; the preview is capped at 420 px.
- The restore action never wraps; `flex: 0 0 auto; flex-wrap: nowrap`.
- Existing `--lw-*` tokens are used for gaps and colours; no new ad-hoc spacing
  scale.

## Evidence

Any change to fonts, decoration, label tokens, sidebar composition or preview
layout invalidates all 0.2.0 evidence. Rebuild, reaccept all 13 declared scopes,
and bind the final bytes before release.
